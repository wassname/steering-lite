## Review: bsbench-meanvjp (79f1798..dfd3a41)

### mean_vjp / wiki_mean_vjp — delivery vs vjp_delta: found nothing (clean)

Verified field-by-field: same `_target_mean`/`_class_mean_vjp`/`_unit_direction`/`_valid_mask`, same default `target_layer = n_blocks−3 = 29`, same `skip_first=16`, same layers (6–24 in both logs), same float32 accumulation, same `apply`, no sign reorientation anywhere. `walk.py:136` passes `target_layer` for both new methods; `cfg.target_layer = target_layer` (mean_vjp.py:71) mutates the cfg object that `attach.train` embeds in the returned `Vector`, so it survives `save`/`load` (checked `Vector.save` → `metadata["cfg"]`, `from_dict` roundtrip; both configs registered). Pooled mean over `pos+neg` (equal class sizes) equals the average of the class means, so the estimator matches the docstring. Minor: mean_vjp.py:62 drops vjp_delta's duplicate-layers and target-bounds validation (cosmetic only).

**F1 — `_wikitext_like` decode→re-encode can shift token counts (mean_vjp.py:53).** Cutting `ids[:length]` can split a multi-byte UTF-8 character (contexts contain Japanese/CJK), producing `` on decode; re-encoding then yields a length different from the matched persona prompt, so "same positions, same compute" holds only to ±1–2 tokens. Also 922/1024 contexts contain WikiText's ` @-@ ` artifacts (checked the JSON). Effect: small jitter in position counts vs the persona-matched claim; unlikely to move results. Probability real: ~0.5 that some contexts shift by ≥1 token; impact low. Cheapest check: `len(tok(tok.decode(ids[:L])).input_ids) == L` over the 512 pairs.

**F2 — docstring overstatement (mean_vjp.py:10).** "wiki_mean_vjp … does not depend on the persona prompts' own context" — it still uses the persona cotangent c and persona-matched lengths. Cosmetic.

### suppressed_mean_diff vs source repo: mostly faithful

**F3 — layer indexing: found nothing.** Source `delayed_readout.py:46-48,146` uses EARLY/PEAK/OUTPUT = 23/25/32 on a residuals stack that includes the embedding row (`hidden_states[:-1] + raw_final`), so residuals[23] = block 22 output, residuals[32] = last block pre-norm. The new code's `round(frac·32)−1, n_blocks−1` (suppressed_mean_diff.py:98) gives exactly blocks 22/24/31 on this 32-block model (log confirms). Caveat: the hard-coded fractions+`−1` only reproduce the source on 32-block models; on any other model they silently shift. Probability of affecting this run: ~0.

**F4 — scoring/basis: found nothing.** rise/fall, per-prompt vocab mean-centering, `min(relu,relu)`, `(W_U − mean)[ids]·gain`, QR — all match `suppressed_activation_subspace.py`. `gain = final_norm(ones)` ≈ weight/√(1+eps) ≈ the source's `rms_norm_gain`; hidden states are pre-final-norm; last-token selection matches.

**F5 — the documented deviation is what breaks the method (suppressed_mean_diff.py:78).** The source does per-sample top-k on one prompt's content tokens; this code averages scores over 256 prompts then takes topk(±diff). Averaging selects tokens with tiny but *consistent* swings, which are rare multilingual fragments — the log's basis tokens are 'ůsob', '关灯', '列車', '코드', etc., i.e. token-frequency noise, not "thought but not said" content. The "energy kept" diagnostic itself is valid (random-subspace null is exactly rank/d = 0.0125; observed 0.008–0.019 ≈ chance at every layer), but note the projection is renormalized (line 110), so a chance-level overlap does not shrink the dose — the delivered vector is effectively a random unit vector inside a junk subspace. Excluding it from results was correct; the conclusion should read "the pooled-contrast variant fails," not "suppressed-activation subspaces don't transfer." Probability real: 0.9. Cheapest check: already in the logs.

### Statistics / reading of the result

**F6 — the "tie" and "random-level" conclusions are weakly identified.** One seed, 20 questions. The hierarchical bootstrap resamples "seeds with replacement" — with one seed that level is degenerate, so the CIs for mean_vjp/wiki_mean_vjp reflect question noise only and omit seed variance (visible in random's 11-seed spread and in vjp_delta's wider CI). Dose selection per side on the same 20 questions adds winner's-curse. wiki_mean_vjp +0.71 [0.18,1.22] vs vjp_delta +0.70 [0.12,1.62] vs mean_vjp −0.26 [−0.84,0.51] are mutually consistent; this run cannot rank the methods. Since all methods share the 20 questions, a paired per-question difference would be far more informative than the unpaired CIs shown. Probability real: 0.95. Cheapest check: rerun with seeds 1,2 (extraction is the cheap part) or compute paired per-question on−off differences from the cached judge scores.

**F7 — footgun inherited, not triggered:** vector cache path is `{method}_s{seed}.safetensors`, ignoring `--target-layer`/`--layers`/`--n-pairs`; a rerun with different extraction args silently reuses a stale vector. Same pattern as vjp_delta, so no differential effect on this comparison.
